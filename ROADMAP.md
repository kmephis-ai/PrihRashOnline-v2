# ПрихРасхOnline v2 — Roadmap

Девиз проекта: **простота, гибкость, функциональность, модульность, сопровождаемость**.

## Обязательная целевая концепция

Дашборд доходов развивается как небольшое приложение внутри Google Sheets:

- единая панель управления;
- режимы просмотра вместо постоянной прокрутки длинного листа;
- быстрые кнопки и пользовательское меню;
- автоматическое скрытие ненужных блоков;
- переход от показателя к исходным операциям;
- подсказки и автоматические выводы;
- обновление и проверка данных одной командой;
- экспорт красивого отчёта;
- поддерживаемый Apps Script с версионностью в GitHub.

## Жёсткие ограничения

1. До отдельного решения разрабатывается **только дашборд доходов**.
2. Новые листы создавать запрещено.
3. Целевое общее количество листов — **не более 10**.
4. Текущее превышение лимита не устраняется удалением вслепую: сначала проводится карта зависимостей и проект консолидации.
5. Реальные финансовые операции не выгружаются в GitHub.
6. ИИ не изменяет финансовые данные автоматически без подтверждения.
7. Визуализация, стильность, современность и цельность интерфейса имеют приоритет над расширением функциональности.
8. Любое изменение должно сохранять единую структуру, логику, терминологию и дизайн-систему.

## Принципы автопилота

- развитие идёт крупными законченными релизами;
- DEV изменяется автономно;
- каждая запись проверяется обратным чтением;
- финансовые данные защищены fail-closed;
- запись в `01 Операции` возможна только контролируемым циклом backup → write → readback → audit;
- PROD, опасные миграции и merge при блокерах запрещены;
- новые листы не создаются;
- до завершения доходного дашборда автопилот не переходит к расходам, бюджетам и другим подсистемам.

# Программа развития дашборда доходов

## Этап 1. Интерактивные режимы просмотра

Режимы:

1. Обзор
2. По годам
3. По месяцам года
4. Выбранный месяц
5. Структура и стабильность
6. Операции
7. Прогноз
8. Качество данных
9. Полный дашборд

Скрипт должен:

- показывать только нужные строки;
- скрывать остальные разделы;
- перемещать пользователя к началу экрана;
- сохранять выбранные год и месяц;
- не затрагивать расчётные диапазоны.

## Этап 2. Кнопки и пользовательское меню

Команды:

- Обновить дашборд
- Текущий год
- Текущий месяц
- Сбросить фильтры
- Показать полный отчёт
- Скрыть подробности
- Открыть операции периода
- Проверить качество данных
- Создать PDF
- Сделать снимок показателей

Меню: `ПрихРасхOnline → Дашборд / Проверка / Экспорт / Настройки`.

## Этап 3. Интерактивная боковая панель

Период:

- год;
- месяц;
- режим просмотра;
- вид анализа.

Фильтры:

- вид дохода;
- регулярный или специальный доход;
- диапазон суммы;
- наличие описания;
- только крупные операции;
- только проблемные записи.

Действия:

- применить;
- сбросить;
- открыть операции;
- экспортировать;
- обновить расчёты.

Краткая сводка:

- доход периода;
- изменение;
- базовый доход;
- специальные доходы;
- число операций;
- индекс стабильности;
- индекс качества.

## Этап 4. Drill-down до исходных операций

Каждый показатель должен открывать связанные операции. Поддерживаемые варианты:

- временный фильтр на `01 Операции`;
- фильтр-представление;
- список в боковой панели;
- переход к первой найденной строке.

Приоритетные drill-down:

- доход месяца;
- специальные доходы;
- категория `Другое`;
- крупные операции;
- возможные дубли;
- проблемы качества.

## Этап 5. Executive-экран

Карточки первого уровня:

- доход выбранного года;
- доход выбранного месяца;
- изменение месяц к месяцу;
- изменение год к году;
- базовый доход;
- специальные доходы;
- прогноз года;
- индекс стабильности;
- качество данных.

Карточки второго уровня:

- активные месяцы;
- средняя операция;
- крупнейший источник;
- доля `Другое`;
- число крупных операций;
- возможные дубли.

Автоматические выводы должны объяснять причины изменений, а не только показывать цифры.

## Этап 6. Единая дизайн-система

Сетка:

- фиксированная ширина карточек;
- одинаковые интервалы;
- строгое выравнивание;
- одинаковые размеры однотипных графиков;
- единая левая граница таблиц;
- свободное пространство между блоками.

Цветовая логика:

- тёмно-синий — структура и навигация;
- голубой — информация;
- зелёный — положительная динамика;
- красный — отрицательная динамика и ошибки;
- янтарный — предупреждения;
- серый — второстепенные показатели;
- бирюзовый или фиолетовый — прогноз.

Графики:

- факт — насыщенная линия или столбцы;
- предыдущий период — светлая линия;
- прогноз — пунктир;
- специальные доходы — отдельный оттенок;
- базовый доход — нейтральный основной оттенок;
- минимум декоративных легенд;
- подписи только ключевых значений.

## Этап 7. Единое обновление

Цикл Apps Script:

1. Проверить `01 Операции`.
2. Проверить обязательные поля.
3. Найти возможные дубли.
4. Обновить технические расчёты.
5. Обновить даты и статусы.
6. Пересчитать выводы.
7. Обновить дашборд.
8. Записать результат в `10 Контроль`.

Триггеры допускаются при открытии, после добавления операции, после Google Forms, раз в день и вручную.

## Этап 8. Интерактивное качество данных

Для каждой проблемы должно быть действие:

- без даты → показать строки;
- без описания → открыть для заполнения;
- `Другое` → начать классификацию;
- возможные дубли → сравнить;
- крупные суммы → подтвердить;
- нулевые суммы → исправить или исключить.

Дополнительная команда: `Исправить следующую проблему`.

## Этап 9. Интеллектуальная классификация

Помощник анализирует описание, сумму, повторяемость и похожие операции, затем показывает категорию, уверенность и обоснование.

Безопасный цикл:

1. предложить;
2. объяснить;
3. получить подтверждение;
4. сохранить правило.

## Этап 10. Экспорт и отчётность

Экспорт:

- PDF за месяц;
- PDF за год;
- семейный финансовый отчёт;
- отчёт по специальным доходам;
- отчёт о качестве данных.

Экспортная версия не содержит служебные диапазоны и элементы управления, но содержит выбранные графики, дату, выводы и номер версии.

## Этап 11. Снимки показателей

Снимки хранятся в существующем `10 Контроль`, без создания нового листа:

- дата;
- доход года;
- доход месяца;
- прогноз;
- индекс стабильности;
- индекс качества;
- число операций;
- число проблем.

# Крупные релизы

## v0.6.0 — Modern Income Dashboard

Приоритет: **визуализация, современность, цельность интерфейса**.

Состав:

- единая дизайн-система;
- современный executive-экран;
- режимы просмотра;
- последовательность блоков 1–13;
- скрытие ненужных блоков;
- навигация и быстрые действия;
- ремонт и унификация диаграмм;
- базовые автоматические выводы;
- запрет создания новых листов;
- UX-контракт и регрессионные проверки.

Критерии готовности:

- дашборд воспринимается как приложение, а не длинная таблица;
- нет пустых диаграмм;
- основной экран читается без горизонтальной и чрезмерной вертикальной прокрутки;
- режимы корректно показывают свои разделы;
- все блоки доступны в полном режиме;
- единая палитра, сетка, размеры и типографика;
- формулы и операции не повреждены;
- повторное применение оформления идемпотентно.
