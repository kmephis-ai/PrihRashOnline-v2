# Roadmap 10.5 — Phase 2: Income Sidebar

## Назначение

Боковая панель упрощает ежедневную работу с дашбордом доходов и не изменяет финансовые операции.

## Возможности

- выбор одного из 10 режимов `14 Аналитика`;
- выбор только годов, реально присутствующих в доходных операциях;
- выбор месяца;
- выбор только категорий, реально присутствующих в доходных операциях;
- настройка минимальной суммы детализации;
- переход к последнему периоду;
- сброс фильтров;
- открытие проблемных операций;
- аудит действий через Foundation, когда он доступен.

## Контракт безопасности

- `01 Операции` используется только для чтения годов и категорий;
- изменяются только управляющие ячейки `14 Аналитика`;
- все параметры повторно проверяются на сервере;
- неизвестные режимы, годы, месяцы и категории блокируются;
- отрицательные и некорректные суммы блокируются;
- установщик не создаёт дублирующий `onOpen` trigger.

## Проверки

```bash
node --check IncomeSidebarController.js
node tests/income_sidebar_validation_test.js
```

GitHub Actions workflow `Income Sidebar Safety` запускает обе проверки для PR и push рабочей ветки.

## DEV-публикация

1. Опубликовать `IncomeSidebarController.js` и `IncomeSidebar.html` через `clasp push`.
2. Запустить `prhInstallIncomeSidebar`.
3. Обновить DEV-книгу.
4. Выполнить `Панель доходов → Проверить панель`.
5. Открыть панель и проверить режим, год, месяц, категорию и минимальную сумму.
6. Подтвердить чтением, что тестовые операции не изменились.

До завершения этого сценария PR остаётся draft.
