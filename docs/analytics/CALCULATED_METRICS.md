# ANL-072 — безопасные вычисляемые и оконные метрики

## Назначение

`PRH_ANALYTICS_CALCULATED_METRICS_V1` — чистый аналитический слой поверх уже рассчитанных `AnalyticsResult` и `PRH_ANALYTICS_PERIOD_RESULT_V1`. Он не читает таблицы самостоятельно, не меняет транзакции, не определяет финансовую истину и не содержит собственных формул доходов, расходов, cash flow или других KPI. Источниками финансовой семантики остаются `FIN-TRUTH-v1`, KPI Dictionary, `ANL-010`, semantic registry `ANL-070` и period/comparison engine `ANL-071`.

Задача слоя — безопасно выполнять ограниченный набор преобразований, необходимых для аналитики и будущего BI-интерфейса, не открывая поверхность для произвольного кода или пользовательских формул.

## Граница полномочий

Контракт не имеет authority на финансовую запись, хранение, сеть, I/O, renderer или UI. Он принимает только типизированные результаты существующего аналитического движка с валидной provenance. Если результат усечён, имеет неподходящий контракт, нарушенную provenance или несовместимую структуру сравнения, операция завершается fail-closed.

Произвольные JavaScript-выражения, `eval`, SQL-выражения, строки формул и другие executable expressions не поддерживаются. Spec имеет точную схему и принимает только перечисленные allowlisted operators и их параметры.

## Операторы

### `SHARE`

`SHARE` вычисляет долю каждой строки полного grouped `AnalyticsResult` в явном denominator scope `RESULT_TOTAL`. Операция разрешена только для allowlisted additive measures и не применяется к отрицательным partition-значениям. Нулевой или отрицательный denominator не превращается в `NaN`/`Infinity`: операция завершается fail-closed.

Доля представляется целым числом в PPM, где `1 000 000` соответствует 100%. Для устранения накопленной ошибки округления используется детерминированное распределение остатка; итог всех долей обязан точно равняться `1 000 000 PPM`.

### `DELTA_ABS` и `DELTA_PCT`

Операторы работают только с primary и comparison series из `ANL-071`. Buckets сопоставляются по порядку лишь тогда, когда число primary и comparison buckets одинаково; несовместимая серия не сравнивается эвристически.

`DELTA_ABS` возвращает разницу в minor units. `DELTA_PCT` возвращает отношение изменения к reference в PPM. Если reference равен нулю, состояние всегда явно: `ZERO_REFERENCE_NO_CHANGE` для `0 -> 0` либо `ZERO_REFERENCE_UNDEFINED` для `0 -> non-zero`. Таким образом, контракт не производит бесконечность и не скрывает семантическую неопределённость.

### `CUMULATIVE`

`CUMULATIVE` проходит primary buckets в порядке period engine и накапливает значение отдельно для каждой комбинации dimensions. Если additive partition отсутствует в конкретном bucket, его значение считается нулём; это не создаёт новую финансовую операцию и не меняет canonical dataset.

### `MOVING_AVERAGE` и `MOVING_MEDIAN`

Окно является целым положительным числом с верхней границей контракта. Политика `REQUIRE_FULL` оставляет начало ряда в состоянии `WINDOW_INCOMPLETE`, пока окно не заполнено. Политика `ALLOW_PARTIAL` разрешает ранние неполные окна и явно маркирует их как `OK_PARTIAL_WINDOW`.

Среднее и медиана округляются детерминированно по правилу `HALF_AWAY_FROM_ZERO_MINOR_UNIT`. Никакой wall-clock или случайности в расчётах нет.

### `TOP_N_OTHER`

`TOP_N_OTHER` применяется к полному grouped `AnalyticsResult`. `N` ограничен контрактом. Строки сортируются по значению по убыванию, а равные значения — по canonical serialization dimension key по возрастанию. Остальные строки объединяются в стабильный bucket `__OTHER__`.

Сумма Top-N и `Other` обязана точно совпадать с суммой исходного результата. Усечённый `AnalyticsResult` отклоняется, поскольку иначе `Other` нельзя доказуемо reconcile с canonical total.

## Числовая модель

Денежные значения остаются целыми safe minor units. Для промежуточной арифметики, где произведение может выйти за безопасный диапазон `Number`, используется целочисленная `BigInt`-арифметика; наружу возвращаются только значения, которые снова доказуемо помещаются в safe integer. Ratio не хранится как floating point: используется масштаб `1 000 000 PPM`.

## Privacy и observability

Публичные тесты используют только synthetic finance fixtures. Spec не содержит transaction rows, amount payload, account/category/member/project IDs или других приватных финансовых данных. Telemetry ограничена schema/version, operator, measure ID, типом источника, размером окна или Top-N, счётчиками входа/выхода, reason/decision и версиями upstream contracts. Финансовые значения и dimension values в telemetry запрещены.

## Совместимость и rollback

ANL-072 не меняет `ANL-010`, `ANL-070`, `ANL-071`, canonical transaction schema или существующие dashboards. Его можно удалить вместе с собственными contract/test/doc/gate файлами без миграции данных и без изменения финансовой истины. Downstream `BENCH-070` и `ANL-073` смогут использовать этот слой только через versioned contract, а не через копирование вычислительной логики в UI.
